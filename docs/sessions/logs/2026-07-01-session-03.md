## Ngã rẽ / quyết định đã chốt với user
- **Swagger (code-first) vs `openapi-generator` (contract-first)** với dự án DDD-first → chốt **code-first**: domain là nguồn chân lý, controller là driving adapter mỏng → sinh spec ngược ra là trung thực; `openapi-generator` sinh server stub generic sẽ chống lại vertical-slice/CQRS/`Result`. `openapi-generator` chỉ dùng ở **phía FE** như client generator. → [ADR 0001](../../design/adr/0001-api-documentation-strategy.md).
- User yêu cầu: **thực hiện** + viết ADR; sau đó **commit `infra/openapi-swagger` + mở PR** và **cập nhật checklist + session log**.

## Quyết định kỹ thuật then chốt
- **KHÔNG dùng `@nestjs/swagger` CLI plugin.** Repo chạy mọi thứ qua `ts-node` (`start`, script gen), không qua `nest build`; plugin là TS transformer chỉ chạy khi build → sẽ không áp dụng dưới ts-node. Dùng **decorator tường minh** → spec deterministic ở mọi runtime (kể cả CI).
- **1 nguồn duy nhất** `src/swagger.ts` (`buildOpenApiDocument`) cho cả Swagger UI (`main.ts`) lẫn script gen → UI và spec commit không lệch.
- **Script gen chạy Nest "preview mode"** (`NestFactory.create(AppModule, { preview: true })`) → quét route metadata nhưng KHÔNG khởi tạo provider → không cần DB/network trong CI.
- **DDD purity:** không nhét decorator Swagger vào `libs/ddd`; tạo `IdResponseDto` ở `libs/api-docs` chỉ để tài liệu hoá shape `IdResponse`.
- **Chống drift:** `openapi:check` = gen + `git diff --exit-code` (mirror `map:check`) → bước CI.
